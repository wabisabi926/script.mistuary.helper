## 硬约束：皮肤在插件未完工前必须能正常用

这不是"尽量"，是**每个里程碑的验收门槛**。三道保险：

1. **皮肤侧只加分支，不替换**：新条件写进已有 `<variable>`，原来那行无条件 `<value>` 永远留在最后当兜底。
2. **`addon.xml` 不写 `<import addon="script.mistuary.helper"/>`**：写了就是硬依赖，没装插件的用户整个皮肤加载失败。只用 `System.AddonIsEnabled` 软探测。
3. **任何失败按"未装"处理**：插件返回空 / 超时 / 版本太低 → 皮肤落到原分支，不弹错误框。

每个里程碑结束后必须过这张表：

| 验证项 | 标准 |
|---|---|
| 卸载插件后 | 相关功能与改动前**完全一致** |
| 禁用插件（不是卸载） | 同上 |
| 插件版本低于要求 | 同上 |
| `audit_skin.py --strict`（皮肤仓库） | EXIT=0 |
| 单测（本仓库） | 全绿 |

## M1a 搜索桥（插件侧）

**交付**：`lib/emby.py` 的 `search()` / `normalize()` / `render_search()`。

**关键决策**：
- 直接读 Emby 插件的 `servers_*.json`，用户不用二次输入地址和令牌
- 地址优先级 `ServerUrl → ManualAddress → LocalAddress → RemoteAddress`（实测四个，文档原来只写了三个）
- `ServerRemoved=true` 的配置跳过（换过服务器后旧配置不删只置标记）
- 缓存只存 `PrimaryImageTag`，**不存完整图片 URL**（URL 带 `api_key`，落盘就是泄露令牌）

**验收**：HTTP 全 mock；当前共 **82 项**单测全绿。

**回退**：不接皮肤分支就没有任何行为变化。

## M1d 搜索补齐：演员 / 类型 / 首字母严格性（暂缓）

**2026-10-30 决定：暂缓，不进 0.1/0.2。** 理由：皮肤搜索只有电影 / 剧集两个容器，
用户又只有 26 个字母输入；`JW` 会命中姜武 / 姜文 / 贾伟等多个人，把他们的作品并进来噪音大于收益。
等皮肤有「人物」结果页签或用户反馈需要时再做，方案保留在下面。

**为什么单列**：README 和 1.3.1 的提交说明都写了「演员 / 类型能搜到」，但 2026-10-30 实测
`/Items?searchTerm=` 不索引演员和类型，搜「姜文」「周润发」「科幻」都是 0 条。这是**功能缺口**，
不是皮肤接线问题。

**已验证可用的 Emby 接口**：

| 能力 | 接口 | 实测 |
|---|---|---|
| 演员 | `GET /emby/Persons?searchTerm=JW` | 返回姜武 / 姜文 / 贾伟（首字母也能命中） |
| 演员作品 | `GET /emby/Items?PersonIds=1856&IncludeItemTypes=Movie` | 姜文 8 部，含让子弹飞 |
| 类型 | `GET /emby/Genres?searchTerm=科幻` | 返回「科幻」「科幻奇幻」 |
| 类型作品 | `GET /emby/Items?Genres=科幻&IncludeItemTypes=Movie` | 正常返回 |

**要做的**：

1. 标题 / 原名 / 拼音：保持现在的 `/Items?searchTerm=`。
2. 演员：`Persons → PersonIds → Items`，结果与标题结果并集去重。
3. 类型：`Genres → Genres=` 过滤，结果并集去重。
4. 首字母严格性（待决策）：给 `FIELDS` 加 `SortName`，纯 ASCII 查询时可选
   `SortName.startswith(query)` 过滤，让 `RZD` 只出 1 条而不是 3 条。

**必须先定的 UX**（见决策记录）：搜 `JW` 是列「姜文 / 姜武」这些人，还是直接列他们的作品？
皮肤搜索结果只有电影 / 剧集两个容器，没有人物容器。选项：

| 方案 | 行为 | 代价 |
|---|---|---|
| A（推荐，先做） | 演员命中后，把其作品并入电影 / 剧集结果 | 结果可能偏多，需要按 PersonIds 分批取 |
| B | 不做演员，只做类型 | 与文档承诺不符，但实现最简单 |
| C | 皮肤新增「人物」结果页签 | 皮肤改动大，不建议现在做 |

**分页**：并集后 offset 语义会变。建议先取 `limit` 为 `page_size` 的标题结果 +
`page_size` 的人物作品，合并去重后按相关性排序；「加载更多」只在标题结果里翻页，
人物作品取前 N 部即可。实现时在 `emby.py` 里写清楚。

**验收**：搜 `JW` 能看到姜文作品；搜「科幻」能看到类型作品；`RZD` 行为符合最终决策；
单测覆盖并集去重、空人物、类型无命中、分页边界。
**估时**：1–1.5 天（含测试）。**皮肤零改动**。

## M2 豆瓣评分

**交付**：`lib/douban.py` 双通道取分（legacy + frodo 签名）、7 天缓存、失败退避、
写 `Window(home)` 的 `Mistuary.Rating.{Douban,Votes,FetchedAt,Status}`。

**已确认的产品规则**（2026-10-30）：

1. 插件只补豆瓣，不接管 IMDb / TMDb / 烂番茄。
2. 主评分「豆瓣」档：详情页优先读插件属性（`Status=ok`），修掉「贴豆瓣图标显示 IMDb 数字」的旧坑；
   列表页拿不到窗口属性，仍读 `ListItem.Rating`。
3. 次评分新增「自动 / TMDb / 烂番茄 / 豆瓣」四档，默认自动；一行仍最多两个胶囊。
4. 单集不显示豆瓣。
5. 豆瓣取分与 Emby 解耦：`dbid → IMDb id` 走 Kodi JSON-RPC，没有 Emby 也能用；搜索仍依赖 Emby。

**条目识别（M2 第一个要定死的点）**：Emby 动态节点的 `DBID` 可能是 0，
不能只靠 `dbid`。皮肤调用时带三个参数，插件按顺序试：

```
RunScript(script.mistuary.helper,action=rating,dbid=…,imdb=…,tmdb=…)
```

1. `dbid > 0` → Kodi JSON-RPC `VideoLibrary.GetItemDetails` 的 `uniqueid`；
2. 否则用皮肤传的 `imdb` / `tmdb`；
3. 都为空 → `Status=missing`，皮肤隐藏胶囊。

`ListItem.UniqueID(imdb)` 在 Kodi 21/22 可用，但 Emby 动态条目是否写入需要实机确认；
确认不了就退回 `title + year` 搜索（豆瓣搜索接口），这条作为兜底。

**皮肤侧**：详情页 `onload` 调 `RunScript(…,action=rating)`；评分行加插件豆瓣胶囊与次评分设置；
`Status != ok` 时整颗隐藏。

**风险**：豆瓣接口变更 / 风控。处置：双通道互备 + 失败缓存 30 分钟 + `Status=error` 让皮肤隐藏。
**进度（2026-10-30）**：插件侧 + 皮肤侧都已接完，待实机。

- 插件：`lib/douban.py`、`tests/test_douban.py`，当前 82 项单测全绿；实网验证让子弹飞 9.0、
  20之后 8.2、阿凡达 8.8。
- 皮肤：`DialogVideoInfo` onload 清状态 + `RunScript(...,dbid,imdb,type)`，
  `NaraOnlineRatingsRow` 加豆瓣胶囊与次评分优先级，媒体分类新增「次评分来源」
  四档（自动 / TMDb / 烂番茄 / 豆瓣），帮助条 31784。
- 修了一个调用 bug：`RunScript(a,b,c)` 会按逗号拆参数，入口原来只读 `argv[2]`，
  现在用 `&` 拼回 `argv[2:]` 再解析。
- 兜底：没有 IMDb 时按标题 + 年份查豆瓣（标题走窗口属性，避免逗号拆参数）；
  实测「让子弹飞/2010」命中 9.0，年份写 1999 返回 missing。

**估时**：2 天。

## 决策记录（2026-10-30）

### 搜索接线（M1b 前置）

1. 搜索页签只保留**电影 / 剧集**，不加单集；单集结果缺季集上下文，放 M4 按需再说。
2. 开关放「媒体」分类、**默认开**；设置名用 `helper_search_off` 反向命名（`Skin.HasSetting` 未设置返回 false）。
3. 排序冲突用**方案 B**（两套 content 用 include 条件切），不先删 `sortby`——本地 XSP 是没装插件用户的唯一路径，不能拿它做实验。

### 搜索输入的现实限制（2026-10-30 实机）
